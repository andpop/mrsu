## Лабораторная работа 4. Модульное тестирование в Python

### Цель работы
Научиться применять техники проектирования тестовых данных (классы эквивалентности, граничные значения) и реализовывать модульные тесты с использованием различных инструментов Python (`doctest`, `unittest`, `pytest`). Закрепить понимание важности независимости тестов и универсальности проверок.

> **Примечание:** В данной работе ИИ-ассистенты (Qwen, DeepSeek, GitHub Copilot и аналоги) выступают в роли «помощника по написанию шаблонного кода и генерации тестовых данных». Ваша задача как инженера — обеспечить математическую корректность, независимость тестов и правильное использование параметризации, чтобы избежать дублирования кода и снизить затраты на поддержку.

### Задания

1. Требуется написать функцию для нахождения корней уравнения `ax^2+bx+c=0` и выдачи их в порядке возрастания. Составить в файле `equation.txt` чек-лист с наборами данных для тестирования (значения `a`, `b`, `c` и ожидаемый результат) с краткими описаниями каждого проверяемого кейса. Необходимо предусмотреть максимальное количество проверяемых случаев (не меньше 6).
   > 💡 **Рекомендация по использованию ИИ (Шаг 1):** 
   > Используйте ИИ для генерации пограничных значений, которые легко упустить.
   > *Пример промпта:* «Ты — QA Automation Engineer. Сгенерируй таблицу тестовых данных (a, b, c и ожидаемый результат) для функции решения квадратного уравнения. Включи случаи: a=0 (линейное уравнение), D=0 (один корень), D<0 (нет действительных корней), очень большие числа, числа с плавающей запятой и случай, когда все коэффициенты равны 0. Оформи в виде Markdown-таблицы».

2. Написать на Python функцию `get_triangle_type` с тремя аргументами, которые интерпретируются как длины сторон треугольника. Функция должна возвращать строку с типом треугольника: "nonequilateral" (разносторонний), "isosceles" (равнобедренный), "equilateral" (равносторонний). Если переданные аргументы некорректны (например, не соблюдается неравенство треугольника или переданы отрицательные числа), функция должна выбрасывать исключение `IncorrectTriangleSides`. Функцию сохранить в файле `triangle_func.py`.

3. Составить в файле `check.txt` чек-лист с наборами данных для позитивного и негативного тестирования функции `get_triangle_type`.

> 🎓 **Советы от преподавателя:**
> 1. **Проблема чисел с плавающей запятой (Float):** ИИ часто генерирует проверку `assert result == 0.3`, что в Python может дать сбой из-за особенностей представления float (например, `0.1 + 0.2 != 0.3`). Всегда используйте `math.isclose()` или `pytest.approx()` для сравнения вещественных чисел. Это классическая ошибка, которую нужно научиться видеть.
> 2. **Параметризация вместо копипаста:** Если вы пишете 5 тестов, которые отличаются только входными данными и ожидаемым результатом, вы делаете это неправильно. Используйте `@pytest.mark.parametrize`. Это делает тесты универсальными, легко читаемыми и резко снижает затраты на их поддержку при изменении кода (один из ключевых принципов качественной автоматизации).
> 3. **Независимость тестов:** Убедитесь, что ваши тесты в `unittest` и `pytest` не зависят от порядка запуска. Каждый тест должен создавать свой собственный объект `Triangle` или вызывать функцию с новыми данными, а не полагаться на состояние, оставшееся от предыдущего теста.
